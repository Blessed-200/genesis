Block 1
BLOCK_NAME: BladeIndexDomainGuard
ROLE: Enforce 4-bit blade index validity for all runtime indexing.
ASSUMPTIONS: Caller can use checked ctor in non-hot paths.
INVARIANTS:
1) BladeIndex::new accepts iff idx<=15.
2) as_usize is total over valid domain.
PROBLEM: Unsafe constructor is public and may be misused outside controlled loops.
INEVITABLE_SOLUTION: Restrict new_unchecked visibility to crate or add debug assertion wrapper macro for all internal uses.
WHY_BRIEF: Minimizes UB surface without affecting optimized hot loops.
PSEUDOCODE:
```rust
pub(crate) const unsafe fn new_unchecked(idx:u8)->Self { debug_assert!(idx<16); Self(idx) }
```
SMT_ASSERTION: (assert (forall ((x Int)) (=> (and (<= 0 x) (<= x 15)) (valid (new x)))))
CYCLES_ESTIMATE: ~0 in release (debug-only assert).
HARDWARE_FALLBACK: N/A.
PATCH: Change visibility of new_unchecked to pub(crate).
RISK: External users relying on unsafe ctor must migrate.
CONFIDENCE: 0.90.

Block 2
BLOCK_NAME: CliffordSignConstKernel
ROLE: Compute algebraic sign from transposition parity and metric contractions.
ASSUMPTIONS: usize::BITS >= 16; two's complement.
INVARIANTS:
1) Output ∈ {+1,-1}.
2) parity_sign and metric_sign each ∈ {+1,-1}.
3) CAYLEY_SIGN generated by exhaustive 16x16 evaluation.
PROBLEM: Bit-iteration per call is optimal for const-build, not for hypothetical runtime recomputation.
INEVITABLE_SOLUTION: Keep const kernel as oracle, enforce all runtime accesses through table lookup only.
WHY_BRIEF: Removes dynamic bit loops from hot path and locks deterministic latency.
PSEUDOCODE:
```rust
let sign = CAYLEY_SIGN[a][b];
let blade = a ^ b;
```
SMT_ASSERTION: prop_table_matches_kernel(a,b): CAYLEY_SIGN[a][b]==compute_clifford_sign(a,b)
CYCLES_ESTIMATE: table lookup ~3-5 cycles L1.
HARDWARE_FALLBACK: Scalar lookup identical.
PATCH: Add #[inline(always)] to table accessor only; discourage direct kernel runtime calls in docs.
RISK: None if API unchanged.
CONFIDENCE: 0.97.
